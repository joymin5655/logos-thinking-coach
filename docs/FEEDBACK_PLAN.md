# 멘토 피드백 반영 계획

> 작성 2026-10-12 · 대상: 페이스메이커스 최종 심사 의견(윤덕주 멘토) · 범위: 웹 MVP(이 레포)와 검증 계획

## 1. 받은 의견 요약

| # | 의견 | 우리가 받아들인 과제 |
|---|---|---|
| A | 강점: 창업자 경험에서 나온 문제의식, 연구 근거, "답을 주지 않는 AI"라는 반대 방향 포지셔닝 | 이 포지셔닝을 제품 안에서 체험으로 증명한다 |
| B | 논리력이 실제로 좋아지는지 검증 데이터가 없다 | 측정 장치를 MVP에 넣고, 파일럿으로 데이터를 만든다 |
| C | 성장은 느리게 체감되므로, 눈에 보이지 않으면 금방 이탈한다. 리텐션이 가장 어렵다 | 한 번의 세션 안에서 변화가 보이게 하고, 매일 돌아올 이유를 만든다 |
| D | 일반 AI 대화와 무엇이 다른지 사용자가 느끼는 구조인지 검증해야 한다 | 차이를 화면 구조로 드러내고, 사용자 체감을 매 세션 묻는다 |
| E | 세션 완주율을 핵심 지표로 둔 방향은 맞다. 다만 초기 유입 동기와 습관화 전략이 구체적이어야 한다 | 유입 동기 3가지와 10분 습관 루프를 설계하고 지표를 하나로 정리한다 |

## 2. MVP에 반영한 것

### B. 검증 데이터 → 측정 장치를 제품에 넣었다
- **3분 사고력 진단**: 처음 들어오면 짧은 논증 하나를 쓰고 채점받는다. 이 점수가 기준점이 되고, 28일 뒤 재진단을 안내한다.
- **같은 루브릭**: 모든 채점은 100점 루브릭 하나로 통일했다. 논리적 일관성 30, 근거의 구체성 40, 방어력·메타인지 30이다(`Scoring_Rubric_Algorithm.md`).
- **코치와 채점관 분리**: 질문하는 모델(Claude Sonnet 5.5)과 채점하는 모델(Claude Haiku 5.5)을 나눴다. 코치가 자기 세션을 후하게 평가하지 않게 하려는 장치다.
- **기록 저장과 내보내기**: Google 로그인(Supabase)으로 기록을 계정에 저장한다. 참가자는 설정에서 자기 기록을 JSON으로 내려받거나 삭제할 수 있다.
- **운영자 지표 화면(`/admin`)**: 운영자만 볼 수 있다. 완주율, 세션 내 Δ, D1/D7 재방문, 설문 평균을 집계해 보여 준다. 파일럿 데이터는 이 화면의 CSV로 내려받는다. 글 본문은 빼고 익명 ID가 붙은 지표 행만 담는다.
- **한계**: 점수는 아직 "AI 추정치"다. 사람 채점과 얼마나 일치하는지는 파일럿에서 확인한다(4장).

### C. 성장 체감과 리텐션 → 15분 안에 보이는 변화
- **세션 내 Before/After**: 사용자가 처음 쓴 주장과 마지막에 직접 쓴 정리를 같은 루브릭으로 따로 채점한다. 몇 주를 기다리지 않고 세션이 끝나는 순간 변화량(Δ)을 보여 준다.
- **한 달 전의 나**: 같은 주제나 분야에서 예전에 쓴 답과 오늘 쓴 답을 나란히 놓는다. 점수보다 문장 차이가 더 설득력 있다고 봤다.
- **오늘의 논증(10분)**: 매일 주제 하나에 입장을 정하고 근거를 쓰면, AI가 가장 약한 고리를 세 번 묻는다.
- **연속 기록과 쉬어가기**: 주 1회는 하루를 놓쳐도 기록이 끊기지 않는다. 한 번 끊긴 스트릭이 이탈로 이어지는 것을 줄이려는 장치다.
- **다음 세션 예약**: 내일 아침 8시 일정을 캘린더 파일(.ics)로 바로 넣을 수 있다. 푸시 알림 서버 없이 쓸 수 있는 리마인더다.

### D. 일반 AI와의 차이 → 구조로 드러내고 매번 묻는다
- **답이 아닌 빈틈**: 세션 리포트에는 결론이나 조언이 없다. 막힌 지점 3개, 당연하게 여긴 전제, 스스로에게 던질 질문 3개만 보여 준다.
- **질문만 하는 코치**: 사용자가 "그냥 답 알려줘"라고 해도 이유를 한 문장으로 밝히고 질문으로 돌려준다. 프롬프트는 서버에 고정돼 있어 클라이언트에서 바꿀 수 없다.
- **혼란 회복(Recovery)**: 사용자가 막히면 처음 가장 확신했던 지점(anchor)으로 돌아가 더 작은 질문을 던진다.
- **세션 후 10초 설문**: "일반 AI와 대화할 때와 달랐나요?", "이 결론을 내가 스스로 냈다고 느끼나요?"를 1~5점으로 받는다.
- **랜딩 비교 블록**: 같은 고민에 일반 AI가 답 목록을 주는 화면과 LOGOS가 질문 하나를 돌려주는 화면을 나란히 보여 준다.

### E. 유입 동기와 습관 → 진입점 3개, 루프 1개, 지표 하나
- **진입 동기 3가지**: 결정을 앞두고(코칭 세션), 글·발표 전에 논리 점검(코칭 세션), 매일 10분 논증 습관(오늘의 논증).
- **습관 루프**: 오늘의 논증 → 점수와 Δ 확인 → 연속 기록 → 다음 날 일정 예약.

## 3. 핵심 지표 정리

문서마다 달랐던 목표치(완주율 30%, 60%, 70%)를 하나로 맞췄다.

| 지표 | 정의 | MVP 목표 | 측정 위치 |
|---|---|---|---|
| 세션 완주율(1차 지표) | 시작한 세션 중 사용자가 직접 마지막 정리를 쓴 비율 | 60% 이상 | 대시보드, `/admin` |
| 세션 내 평균 상승 | 최종 정리 점수 − 처음 주장 점수의 평균 | +10점 이상 | 세션 리포트 |
| D7 재방문 | 첫 세션 후 7일째 다시 세션을 시작한 비율 | 40% 이상 | `/admin` 지표 |
| 차이 체감 | 설문 "일반 AI와 달랐나요" 평균 | 4.0/5 이상 | 세션 리포트 설문, `/admin` 지표 |
| 4주 진단 변화 | 재진단 점수 − 첫 진단 점수 | 파일럿에서 기준 설정 | 진단 화면 |

## 4. 검증 계획(파일럿)

1. **인터뷰 10~15명**: 진입 동기 3가지 중 무엇이 실제로 사람을 데려오는지 확인한다.
2. **파일럿 A/B, 4~8주, n=40~60**:
   - A군은 LOGOS를 쓰고, B군은 같은 주제를 일반 챗봇과 대화한다.
   - 시작과 끝에 같은 진단 문항을 쓰게 한다.
   - 사전·사후 글은 누가 쓴 글인지 가린 채 사람 2명이 같은 루브릭으로 채점한다. 이 결과로 AI 채점과의 일치도를 보정한다.
   - 보조 지표는 1주 뒤 자기 논거 회상, 자기 보고 자신감, 세션 완주율, D7 재방문이다.
3. **판정 기준**:
   - A군의 사후 점수 상승폭이 B군보다 크고, AI 채점과 사람 채점이 충분히 일치하면 "논리력 향상"을 주장한다.
   - 그렇지 않으면 루브릭과 질문 설계를 고치고 다시 측정한다.
4. **데이터 수집 방식**: 참가자가 로그인해서 쓰면 기록이 Supabase DB에 쌓인다. 운영자는 `/admin`에서 완주율·Δ·D1/D7·설문 평균을 바로 보고, 사람 채점이나 분석에는 관리자 CSV 내보내기를 쓴다. 참가자는 설정에서 자기 기록을 내려받고 삭제할 수 있다.

## 5. 다음 단계와 남은 위험

- **서버 저장(반영함)**: 로그인과 DB(Supabase)로 옮겼고, 운영자가 `/admin`에서 리텐션을 직접 집계한다. 남은 위험은 개인정보다. 처리방침은 법률 검토 전 초안이고, 파일럿 참가자에게 동의를 받는 절차는 검토 뒤에 확정한다.
- **호스팅**: 현재 Vercel Hobby(비상업) 플랜이다. 유료 출시 전에 Pro로 올리고 결제를 붙인다. 그 전까지 가격표는 "출시 예정"으로만 표시한다.
- **AI 채점 신뢰도**: 3단계 루브릭은 점수 해상도가 낮다(5점 단위). 파일럿 결과를 보고 세분화를 검토한다.
- **비용 통제**: API 키는 서버 환경변수에만 있다. 입력 길이·턴 수 제한, 출처 확인, 요청 빈도 제한을 두고, 최종적으로 Anthropic 워크스페이스 지출 한도로 막는다.
- **AI 대전(아레나)**: AI가 반대편에서 3라운드 반론하고, 채점관이 같은 루브릭으로 판정한다. 사용자 간 대전은 로드맵 단계에서 다룬다.
