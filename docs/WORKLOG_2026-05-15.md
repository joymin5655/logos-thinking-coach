### 2. SPA fallback 라우팅 수정

**증상**: `/` 200 OK / `/about` `/dashboard` 등 모두 404 (text/plain)

**진단**: `vercel.json:9`의 rewrite source
```
"/((?!assets/|favicon|logo|robots|sitemap).*)"
```
는 JS regex의 negative lookahead 문법. Vercel은 `path-to-regexp`로 source를 파싱하는데 lookahead 미지원 → 패턴 컴파일 실패 → rewrite 미등록 → 모든 클라이언트 라우트 404.

**조치 (2회 시도)**:

1차 (`02c5595`):
```diff
- "source": "/((?!assets/|favicon|logo|robots|sitemap).*)"
+ "source": "/:path*"
```
→ 여전히 404. `:path*`도 일부 환경에서 미매칭.

2차 (`2d899d8`, 성공):
```diff
- "cleanUrls": true,
- "source": "/:path*"
+ "source": "/(.*)"
```
→ 표준 Vercel SPA 패턴. `cleanUrls`는 SPA 라우트와 충돌 가능해 제거. Vercel은 정적 파일을 rewrite보다 먼저 매칭하므로 `/assets/*` 등 자동 제외됨.

**검증** (12/12 routes 200 OK):
