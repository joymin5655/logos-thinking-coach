# LOGOS 정보 구조(IA)와 화면 설계

작성 2026-10-13 · 상태: 초안 (구현 확인 기준 = `UX uplift` 머지본, 기능 ID·예외·갭 번호는 정합 완료) · 관련 문서: [PRD](PRD.md), [FEATURE_SPEC](FEATURE_SPEC.md), [USER_FLOWS](USER_FLOWS.md), [REVIEW](REVIEW.md)

## 0. 읽는 법

- 순서: PRD → FEATURE_SPEC → USER_FLOWS → **IA_SCREENS**. 플로우 번호(F1..F8)와 `UF#`(플로우 갭)는 USER_FLOWS와 같고, 공통 예외 `E#`와 기능 ID는 FEATURE_SPEC과 같다. 이 문서 고유의 화면 갭은 `S#`다. 2026-10-13에 기능 ID·예외 번호·갭 번호를 FEATURE_SPEC·USER_FLOWS에 맞춰 정합했다.
- 화면 상태는 **구현됨** / **갭**(구현이 없거나 비어 있음) / **계획(Phase 2)** / **해당 없음**으로 적는다. 코드를 읽어 확인한 것만 "구현됨"이다. "계획(Phase 2)" 화면은 2026-10-13 기준 브랜치 `claude/retention-kpi`에 구현돼 있다(PR 대기, 운영 미배포). 실행 확인은 하지 않았다.
- 문구는 `client/src/i18n/ko/*`의 실제 한국어 문구를 짧게 인용한다.
- 계획 화면 중 4개 화면군(대시보드 홈 블록, 세션 리포트 작성 비율, `/welcome`, `/join`)은 2026-10-13에 승인된 목업 보드가 있다: [목업 보드](https://claude.ai/artifact/NLGv7jYeE5ftQL57PbciK6). `/admin` 퍼널·군별은 관리자 전용이라 목업이 없고 기존 `/admin` 스타일을 따른다. 아래 와이어는 ASCII 텍스트이며 시각 디자인이 아니다. 목업과 명세가 다른 9건(M1~M9)은 2026-10-13 사용자 위임으로 모두 결정됐고 §4.9의 "결정" 열에 있다. Phase 2 구현은 끝났다는 보고를 받았으나 코드와 대조하기 전이라 이 문서의 상태 라벨은 "계획"을 유지한다.

## 1. 라우트 트리

```
/                         랜딩                          공개   구현됨
├─ /about                 소개                          공개   구현됨
├─ /features              기능                          공개   구현됨
├─ /pricing               요금                          공개   구현됨
├─ /privacy               개인정보 처리방침(법률 검토 전 초안)  공개   구현됨
├─ /login                 로그인                        공개   구현됨
├─ /auth/callback         로그인 콜백                   공개   구현됨
├─ /404, 그 외 모든 주소    NotFound                      공개   구현됨
│
├─ /dashboard/diagnostic  3분 진단                      공개(비회원 가능)   구현됨
│
├─ /dashboard             홈                            로그인  구현됨
├─ /dashboard/argue       오늘의 논증                   로그인  구현됨
├─ /dashboard/session     소크라테스 코칭               로그인  구현됨 (?resume=<id>)
├─ /dashboard/arena       토론 아레나                   로그인  구현됨
├─ /dashboard/analytics   논리력 분석                   로그인  구현됨
├─ /dashboard/history     세션 기록                     로그인  구현됨 (?kind=arena)
├─ /dashboard/subscription 구독                         로그인  구현됨
├─ /dashboard/settings    설정                          로그인  구현됨
│
├─ /admin                 관리자 지표                   관리자  구현됨 (비관리자는 NotFound)
│
├─ /welcome               첫 실행 온보딩 4단계           로그인  계획(Phase 2)
└─ /join?c=코드           파일럿 참가                   공개→로그인  계획(Phase 2)
```

근거: `client/src/App.tsx`의 `Router`, 보호 라우트는 `guard()`로 `RequireAuth`를 씌운다.

### 권한 규칙

| 구분 | 라우트 | 규칙 | 근거 |
|---|---|---|---|
| 공개 | `/`, `/about`, `/features`, `/pricing`, `/privacy`, `/login`, `/auth/callback`, `/404` | 로그인 불필요. 요금제의 사전 알림 신청만 로그인 필요 | `App.tsx`, `components/PlanCards.tsx:60` |
| 공개(예외) | `/dashboard/diagnostic` | 라우트는 공개이고 서버도 진단 채점만 비회원을 허용한다(IP당 3/일). 다른 `/dashboard/*`는 모두 로그인 필요 | `App.tsx`, `server/logos/handler.ts:249` |
| 로그인 | `/dashboard`와 그 하위(진단 제외), `/dashboard/settings` | 비회원은 `/login?next=<경로+쿼리>`로 이동 (E10) | `components/RequireAuth.tsx` |
| 관리자 | `/admin` | 로그인 + `is_admin` RPC true. 아니면 NotFound(페이지 존재를 숨김) | `pages/Admin.tsx:158` |

참고: 비회원이 `/dashboard/diagnostic`을 열면 대시보드 사이드바가 같이 보이지만, 진단 외 메뉴는 모두 로그인 벽으로 간다. 이 진단 화면으로 가는 공개 링크는 현재 없다(USER_FLOWS UF1). 2026-10-13 결정으로 Phase 2에서 랜딩에 비회원 3분 진단 CTA를 추가한다(3.1).

## 3. 화면 설계

각 화면은 라우트, 목적, 제목·안내 문구, 구성 블록(위→아래), 버튼과 이동, 상태별 화면, 관련 기능 ID 순으로 쓴다. 상태는 **빈 / 로딩 / 오류 / 권한 없음 / 한도 초과**를 모두 적고, 해당이 없으면 "해당 없음"으로 둔다.

공통 상태(모든 화면에 해당하는 것):

- **라우트 로딩**: 청크를 받는 동안 배경색만 채운 빈 화면(`RouteFallback`). 구현됨.
- **예기치 않은 오류**: `ErrorBoundary`가 "예기치 않은 오류가 발생했어요." + "페이지 새로고침" 버튼. 구현됨.

### 3.1 Landing — `/`

- **목적**: 서비스를 설명하고 시작하게 한다. 관련: R8-F1, R8-F4(계획), R7-F2(계획).
- **문구**: 히어로 "스스로 납득하는 힘." / "소크라테스의 문답법으로 당신은 / 논리의 빈틈을 스스로 발견하고 더 깊이 사고합니다."
- **블록**: ① 히어로(3D 배경, 시작하기 / 더 알아보기) ② "이럴 때 LOGOS를 찾아요" 진입 카드 3개(결정을 앞두고 / 글·발표 전에 논리 점검 / 매일 10분 논증 습관) ③ 비교 "같은 고민, 다른 대화"(일반 AI vs LOGOS 질문 하나) + "내 고민으로 해보기" ④ 푸터.
- **버튼**: 시작하기 → `/dashboard`, 더 알아보기 → `/about`, 진입 카드 1·2 → `/dashboard/session`, 3 → `/dashboard/argue`, 비교 CTA → `/dashboard/session`. 모두 비회원에게는 로그인 벽(E10).
- **계획(Phase 2, 2026-10-13 결정)**: 비회원 "3분 진단" CTA를 추가한다 → `/dashboard/diagnostic`(로그인 불필요). 위치는 히어로 버튼 옆과 비교 블록 아래를 가안으로 하고, 문구는 확정 전이다. 첫 방문의 UTM·referrer host는 `logos.ft`에 한 번만 저장하고 `landing_view` 이벤트를 기록한다(초안의 `cta_click`은 구현된 이벤트 목록에 없다)(GPC·DNT가 켜져 있으면 저장·전송하지 않음). 관련: R8-F1, R8-F4, R7-F2.
- **상태**: 빈 해당 없음 / 로딩 공통(청크) 구현됨 / 오류 공통 구현됨 / 권한 없음 해당 없음 / 한도 초과 해당 없음.
- **갭**: 비회원 진단 진입 링크 없음(UF1, FEATURE_SPEC G17) → Phase 2에서 CTA 추가로 해소 예정. 시작 버튼이 모두 로그인 벽으로 직행하는 점은 그대로다.

### 3.2 About — `/about`

- **목적**: 문제의식·연구 근거·로드맵을 설명한다. 관련: R8-F2.
- **문구**: "소크라테스가 / AI가 되다", 섹션 "AI를 쓸수록 생각하는 능력이 줄어듭니다"(MIT Media Lab 2025 등 인용 3건), "사용자가 무너지는 세 가지 장면".
- **블록**: 히어로 → 연구 근거 → 세 가지 장면 → 시장 기회 → 검증 로드맵 → 로드맵 → 팀 → 창업 스토리.
- **버튼**: 상단 시작하기(→ `/dashboard`).
- **상태**: 정적 페이지. 빈·오류·권한·한도 해당 없음. 로딩·예기치 않은 오류는 공통.
- **참고**: 시장 규모·로드맵 수치의 출처 확인은 이 문서 범위 밖(**미확인**). 멘토 의견 ①(검증 데이터 없음)과 관련해 "검증 로드맵" 섹션의 현재 주장 수위를 PRD와 맞춰야 한다.

### 3.3 Features — `/features`

- **목적**: 기능 3개를 한눈에 보여 준다. 관련: R8-F2.
- **문구**: "논리의 빈틈을 / 스스로 발견하다", 카드 3개: 소크라테스 코칭 / 실시간 논리 분석 / 성장 대시보드.
- **블록**: 제목 → 카드 3개.
- **상태**: 정적. 해당 없음 위주.
- **갭**: 기능 카드에 아레나·오늘의 논증·3분 진단이 없다(현재 주요 기능과 불일치). 카드에서 해당 기능으로 가는 링크도 없다(S10).

### 3.4 Pricing — `/pricing`

- **목적**: 요금제와 사전 알림 신청. 관련: R8-F2, R7-F9.
- **문구**: "생각의 깊이에 투자하세요", "지금은 베타라 Free 플랜을 무료로 쓸 수 있어요.", "Pro·Team은 출시 예정이며 가격과 구성은 바뀔 수 있어요."
- **블록**: 월간/연간 결제 전환 → 플랜 카드 3개(Free 현재 플랜, Pro·Team "예정" 라벨, 사전 알림 신청).
- **버튼**: 사전 알림 신청(로그인 필요, 비회원은 토스트 "사전 알림은 로그인 후 신청할 수 있어요." 후 `/login?next=/pricing`), 신청 완료 후 "사전 알림 신청 완료".
- **상태**: 빈 해당 없음 / 로딩 신청 중 "신청하는 중…" / 오류 "신청하지 못했어요. 잠시 후 다시 시도해 주세요." 구현됨 / 권한 없음: 비회원 로그인 유도 구현됨 / 한도 초과 해당 없음.
- **제외**: 결제는 Phase 2 범위 밖(제외).

### 3.5 Privacy — `/privacy`

- **목적**: 수집 항목·이용 목적·보관을 안내한다. 관련: R8-F2, R9(개인정보).
- **문구**: "개인정보 처리방침", 배지 "법률 검토 전 초안", "시행일: 2026-10-13", 문의 `contact@lo9os.org`.
- **블록**: 제목·초안 안내 → 조항 섹션(운영자와 문의처, 수집하는 항목, 이용 목적, …) → 문의.
- **상태**: 정적. 해당 없음 위주.
- **계획 영향**: Phase 2 이벤트 계측(R7-F2), 파일럿 동의(R7-F6)가 들어오면 수집 항목 조항이 바뀌어야 한다. 현재 방침은 "이용 횟수 기록"과 "운영 지표 집계"까지만 적혀 있다(갭 S11).

### 3.6 Login — `/login`

- **목적**: Google 로그인 한 가지. 관련: R6-F1.
- **문구**: 제목 "로그인", "기록을 계정에 저장하고, 어느 기기에서든 이어서 쓸 수 있어요.", 버튼 "Google로 계속하기", 안내 "계속하면 개인정보 처리방침에 따라 기록이 저장되는 것에 동의하는 거예요."
- **블록**: 헤더(로고, 언어·테마) → 카드(제목, 안내, 구성 안 됨 경고, 버튼, 오류, 방침 링크).
- **버튼**: Google로 계속하기 → OAuth → `/auth/callback?next=...`. 이미 로그인했으면 자동으로 `next`로.
- **상태**: 빈 해당 없음 / 로딩 "이동하는 중…" 구현됨 / 오류 "로그인을 시작하지 못했어요. 다시 시도해 주세요." 구현됨 / 구성 안 됨 "로그인 준비 중이에요. 잠시 후 다시 와 주세요." 구현됨 / 권한·한도 해당 없음.

### 3.7 AuthCallback — `/auth/callback`

- **목적**: OAuth 복귀 처리, 끝나면 `next`로. 관련: R6-F1, R6-F3(비회원 기록 이전), R3-F8(계획: 첫 로그인 분기).
- **문구**: "로그인을 마무리하는 중…", 오류 "로그인하지 못했어요" / "로그인 정보를 받지 못했어요. 다시 시도해 주세요." / "로그인 응답이 오지 않았어요. 다시 시도해 주세요."
- **블록**: 중앙 상태 문구 또는 오류 카드(+ "다시 로그인" 링크).
- **상태**: 로딩 구현됨 / 오류(15초 초과 포함) 구현됨 / 나머지 해당 없음. `error_description`은 URL 값을 그대로 보이지 않고 고정 문구로 대체한다.

### 3.8 NotFound — `/404` 및 매칭 없는 주소

- **목적**: 없는 주소 안내. 비관리자의 `/admin`도 같은 화면이다. 관련: R8-F2, R7-F1.
- **문구**: "페이지를 찾을 수 없어요" / "찾으시는 페이지가 존재하지 않아요." / "주소가 바뀌었거나 삭제됐을 수 있어요." 버튼 "홈으로".
- **버튼**: 홈으로 → `/`(랜딩). 로그인 사용자도 `/dashboard`가 아니라 랜딩으로 간다(갭 S12).
- **상태**: 정적. 해당 없음.

### 3.9 DashboardHome — `/dashboard`

- **목적**: 오늘 할 일(이어하기 또는 오늘의 논증)과 내 변화 요약. 관련: R5-F1, R5-F2, R5-F3, R3-F1, R3-F4, R3-F5, R6-F4.
- **제목**: "대시보드"(Dashboard). 첫 줄 라벨 "{날짜} · 연속 {n}일".
- **블록 (위→아래)**:
  1. 이어하기 카드(이어할 코칭이 있을 때만): "이어하기 · 소크라테스 코칭", 주제, 진행 막대 + "{n}/4단계", [이어서 하기].
  2. 오늘의 논증 카드: "오늘의 논증 · 10분", 주제, "입장을 고르고 근거를 쓰면, LOGOS가 가장 약한 고리를 세 번 묻습니다.", [시작하기 / 한 번 더], [내일 아침 8시 캘린더에 추가], 완료 시 "오늘 논증을 마쳤어요." (이어하기 카드가 없으면 이 카드가 hero)
  3. 진단 초대 행(진단 없고 "나중에" 안 눌렀을 때 / 재진단 시기일 때): "3분 진단으로 기준점 만들기 · 시작 →" / "재진단 할 수 있어요 · 시작 →", [나중에 할게요]
  4. KPI 카드(값이 있는 것만): 연속 기록, 세션 완주율, 세션 내 평균 상승, 진단 변화, 아레나 전적
  5. 이번 주 7칸(기록함 / 쉬어감 빗금 / 없음) + 범례 "빗금 = 쉬어가기(주 1회). 하루 놓쳐도 기록이 끊기지 않아요."
  6. 점수 추이 선 그래프(완주 2회 이상) + 한 달 전의 나와 비교 인용 2개(완주 기록 2개 이상)
  7. "기록은 내 계정에 저장돼요" 배지 + [기록 내보내기 (JSON)]
  8. 분야별 완주 횟수(관심 분야를 고른 경우만)
  9. 최근 기록 3건(코칭·논증·아레나 혼합) → 세션 기록으로
- **버튼과 이동**: 이어서 하기 → `/dashboard/session?resume=<id>` / 시작하기 → `/dashboard/argue` / 진단 행 → `/dashboard/diagnostic` / 최근 기록 → `/dashboard/history`(아레나는 `?kind=arena`) / 캘린더·내보내기는 파일 내려받기 + 토스트.
- **상태**:
  - 빈(기록 없음): 구현됨(축소형) — KPI·추이·비교·최근 기록 섹션이 통째로 사라지고, 오늘의 논증 카드와 진단 초대 행, 이번 주 7칸만 남는다. 빈 상태 안내 문구(`recentEmpty`, `trendEmpty`, `compareEmpty`, `deltaEmpty`, `noneStarted`, `diagKpiEmpty`)는 i18n에 정의돼 있으나 화면에서 쓰이지 않는다 → **갭 S1**.
  - 로딩: **갭** — 로컬 캐시를 즉시 그리고, 로그인 직후 서버 기록을 받아 병합하는 동안의 표시가 없다. 새 기기 첫 로그인에서 빈 상태가 잠깐 보였다가 바뀔 수 있다(코드상, 실행 미확인) → S2.
  - 오류: 해당 화면 자체에는 없음. 동기화 실패는 "동기화 대기 N" 배지로만 표시(E9).
  - 권한 없음: 비회원은 로그인 벽(E10) 구현됨.
  - 한도 초과: 홈에서는 해당 없음(한도는 하위 화면에서 발생). 남은 횟수 표시도 없음 → UF4.
- **계획 추가 블록**: 4.2~4.4 참조(주간 리캡 카드, 마일스톤 스트립, 스트릭 위험 배너).

### 3.10 Diagnostic — `/dashboard/diagnostic`

- **목적**: 3분 진단으로 기준점 만들고 재진단으로 변화 보기. 관련: R1-F1, R1-F2, R1-F3, R1-F4(계획).
- **제목**: "사고력 진단"(Thinking Diagnostic).
- **블록 — 작성 화면**: 라벨 "진단 1/1 · 기준점 만들기"(재진단이면 "재진단") + 타이머(MM:SS, 초과 시 "+MM:SS 지났어요") → 문항 카드 "오늘의 진단 문항" + `"{명제}" 동의하나요? 입장과 근거를 3~5문장으로 써 주세요.` → 입력(≤2000자) → "정답은 없어요. 3분은 안내일 뿐, 더 써도 괜찮아요." + 글자 수 + [채점하기] → [지금은 건너뛰기](→ `/dashboard`)
- **블록 — 결과 화면**: "진단 결과 · AI 추정치" → 큰 점수(기준점 또는 이번 진단) + 지난 진단 대비 변화 → 루브릭 3축 막대 → 근거 → (비회원) "로그인하면 기록이 저장돼요" 카드 → "재진단 예정 · {날짜}" 배지 + [지금 다시 진단] [첫 세션 시작] → [홈으로]
- **버튼과 이동**: 채점하기 → 결과 / 첫 세션 시작 → `/dashboard/session` / 홈으로·건너뛰기 → `/dashboard` / 로그인하기 → `/login?next=/dashboard`.
- **상태**:
  - 빈: 첫 진단은 작성 화면이 곧 빈 상태. 구현됨.
  - 로딩: 채점 중 버튼 "채점하는 중" + 입력 잠금 + 점 애니메이션. 구현됨.
  - 오류: `ErrorLine` + 다시 시도(E4·E6). 최소 30자 미달이면 "{30}자 이상 써야 채점할 수 있어요." (글자를 입력하기 시작한 뒤에만 표시) 구현됨.
  - 권한 없음: 비회원도 사용 가능. 로그인 만료 시 E1.
  - 한도 초과: 공통 `ErrorLine` 한도 문구. 비회원 IP 한도도 현재는 같은 문구(UF3). **계획(Phase 2)**: 비회원이 한도를 넘으면 "내일 다시" 대신 "로그인하면 계속할 수 있어요" 안내와 [로그인하기](→ `/login?next=/dashboard/diagnostic`)를 보인다(가안, 2026-10-13 결정).
- **갭**: 문항 순환이 `진단 횟수 % 4`라 교차 출제 규칙이 없다(R1-F4 계획). 비회원 진입 링크 없음(UF1, Phase 2에서 랜딩 CTA로 해소 예정). 비회원 진단은 서버가 점수를 검증하지 않는 것이 기본값이다(2026-10-13 결정).

### 3.11 ThinkingSession — `/dashboard/session` (소크라테스 코칭)

제목 "씽킹 세션"(Thinking Session). 단계별로 나눠 설계한다.

#### 3.11.1 시작 단계 (intro)

- **목적**: 주제를 정하고 시작하거나 이어서 한다. 관련: R2-F1, R2-F5, R5-F2.
- **문구**: "무엇을 생각해 볼까요?" / "답은 주지 않고 질문만 해요. 한 줄이면 충분해요." / 입력 플레이스홀더 "예: 지금 회사를 옮겨야 할지 고민됩니다".
- **블록**: 제목·안내 → 주제 입력(≤200자, Enter 시작 힌트) + [세션 시작] → "이렇게 시작해 보세요" 예시 칩 4개(고민: 지금 회사를 옮겨야 할지 고민돼요 / 결정: 대학원에 갈지 취업할지 정하지 못했어요 / 주장: AI가 일자리를 줄이기보다 늘릴 거라고 생각해요 / 주장: 재택근무가 팀 생산성을 높인다고 믿어요) → 이어하기 줄(해당 시) "이어하기 · {주제} {n}/4단계 · 계속 →"
- **버튼**: 칩 = 주제 칸 채우기(자동 시작 아님), 세션 시작, 이어하기 줄.
- **상태**: 빈 = 기본 화면 구현됨 / 로딩 해당 없음 / 오류 해당 없음(API 호출 전) / 권한 없음 E10 / 한도 초과: 시작 시점에는 모름, 첫 답 전송 뒤 발생(UF4).

#### 3.11.2 대화 단계 (session)

- **목적**: 4단계 질문 대화. 관련: R2-F2, R2-F3, R2-F4.
- **블록**: 좌측(대화) — "Subject {주제}" → 대화 목록(LOGOS 질문은 단계 태그 SURFACE/CHALLENGE/CORE/SYNTHESIS, aporia면 `RECOVERY · 처음 확신했던 지점으로 돌아가요` 라벨 + 점선 주황 테두리, 내 답에는 사용한 신호 버튼 태그) → 오류 줄 → THINK 안내 패널 → 정리 유도 패널 → 입력창(≤1000자) + [보내기]. 우측(데스크톱) — 진행 단계 막대(표면·도전·핵심·통합 + 단계 설명) / 대화 조절 버튼 3개 + 힌트 / "내가 처음 확신한 것" 인용 + [정리하기] + [저장하고 나가기]. 모바일(≤640px)은 우측 패널이 입력창 아래로 밀리고 신호 버튼이 입력창 위 한 줄로 따로 나온다.
- **문구**: 첫 질문 "이 주제에서 지금 가장 확신하는 한 가지는 무엇인가요?", 신호 버튼 "더 파고들어줘 / 이 정도면 됐어 / 내가 더 고민해볼게", 힌트 "같은 지점을 더 날카롭게 묻습니다 / 다음 단계로 넘어갑니다 / 저장해 두고 나중에 이어갑니다", THINK 안내 "충분히 생각해 보세요. 지금까지의 대화는 저장해 두고, 나중에 이어서 할 수 있어요."
- **버튼**: 보내기, 신호 버튼 3개(첫 답 전에는 꺼짐 "첫 답을 쓰면 켜져요."), 정리하기(조건 충족 시 활성, 아니면 "통합 단계에서 한 번 답하거나, 6번 답하면 켜져요."), 저장하고 나가기(→ `/dashboard` + 토스트), 계속하기.
- **상태**: 빈 = 첫 질문만 있는 상태 구현됨 / 로딩 "LOGOS가 질문을 고르는 중" 점 애니메이션 + "응답에 최대 30초 정도 걸릴 수 있어요" 구현됨 / 오류 `ErrorLine` + [마지막 메시지 다시 보내기] (E4·E6), 이전 답을 받지 못한 채 끊긴 세션을 이어서 하면 "이전 답변에 대한 질문을 받지 못했어요." 구현됨 / 권한 없음·401 E1 구현됨 / 한도 초과 `ErrorLine` 한도 문구 + 구독 보기(재시도 없음) 구현됨.

#### 3.11.3 정리 단계 (summary / scoring)

- **목적**: 사용자가 최종 정리를 직접 쓰고 채점받는다. 관련: R2-F6.
- **제목**: "내 말로 정리하기"(Your Synthesis).
- **문구**: "처음 주장" 인용 → "지금은 어떻게 생각하나요?" → "대화에서 발견한 것을 당신의 말로 정리해 주세요. LOGOS는 대신 써 주지 않아요. 30자 이상 써야 점수를 볼 수 있어요."
- **블록**: 인용 → 질문 → 입력(≤1500자) + 글자 수·"최소 30자" → [대화로 돌아가기] [결과 보기].
- **상태**: 빈 = 기본 화면 / 로딩 "채점하는 중" + "점수와 리포트를 만드는 중" / 오류 `ErrorLine` + [다시 채점](성공한 것은 재사용), 일부 실패 시 "일부 결과를 받지 못했어요." / 한도 초과·401은 E1·E2. 모두 구현됨.

#### 3.11.4 리포트 단계 (complete)

- **목적**: 점수 변화와 빈틈 리포트, 설문. 관련: R2-F6, R2-F7.
- **제목**: "세션 리포트"(Session Report).
- **블록**: 좌 — "이번 세션 · {주제}" → 점수 변화(처음 → 최종, "{n}점 상승/하락") → 처음/마지막 인용 → 루브릭 3축 막대(주황 눈금 = 처음 점수) → "AI 추정치예요. 같은 루브릭으로 처음 답과 마지막 정리를 따로 채점하고, 주황 눈금이 처음 점수입니다." + 근거. 우 — "LOGOS는 답 대신 빈틈을 보여줍니다" → 다시 볼 지점 / 막힌 지점 / 당연하게 여긴 전제 / 생각이 움직인 순간 / 스스로에게 던질 질문 → 10초 설문(일반 AI와 대화할 때와 달랐나요? 1~5, 이 결론을 내가 스스로 냈다고 느끼나요? 1~5) → [새 세션] [세션 기록] [홈].
- **상태**: 빈·로딩 해당 없음(결과가 모두 있어야 이 화면이 열림) / 설문 저장 "저장했어요." / 새로고침하면 이 화면은 사라지고 시작 화면으로 돌아감(리포트는 세션 기록에서 재열람) → 갭 S3.
- **계획**: "작성 비율" 카드 → 4.5.

### 3.12 Argue — `/dashboard/argue`

제목 "오늘의 논증"(Daily Argument). 단계: 입장 선택 → 이유 → 반문 3라운드 → 정리 → 결과.
